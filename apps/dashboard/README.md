# @thaipass/dashboard

The control surface for the thaipass gateway. Sidebar shell, five pages, and no server of its own — every call goes from your browser straight to your local proxy, carrying a session cookie that never leaves the machine.

## Pages

| Route | What it does |
| --- | --- |
| `/` | Gateway health, credit balance, catalog mix, and the setup path |
| `/playground` | Streams a prompt through `/v1/chat/completions` and times the first token |
| `/models` | The account's catalog, filterable by kind and availability |
| `/integrations` | Ready-made config for Claude Code, Cursor, Cline, the SDKs, and cURL |
| `/settings` | Gateway origin, session cookie, and theme |

## Running it

```bash
bun dev
```

The dashboard listens on port 3000 and expects the proxy on `http://127.0.0.1:3001`. Change that under Settings if yours differs.

The proxy must allow this page's origin. Loopback on any port is allowed by default; set `AIPASS_CORS_ORIGIN` on the proxy to allow anything else.

## Structure

```
app/            routes; (dashboard) holds the sidebar shell
components/     layout/ chrome, ui/ generated primitives, one folder per page
hooks/          use-connection (localStorage), use-gateway (shared fetches)
lib/            proxy client, catalog helpers, snippets, tokens
```

`components/ui/` is generated by `shadcn add` and by the Rare UI registry — edit those through the CLI, not by hand. `hooks/use-gateway.tsx` owns the only requests to the proxy so the header and the page body share one of each.
